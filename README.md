# 停车轨迹实验室 · Android 原生实验版 v0.1.0

用途：先实测 vivo X200 Pro 在室内、地下室和地下车库的**水平轨迹漂移**，而不是直接做成可依赖的停车找车导航。无云端、无地图 SDK、无车辆 CAN / 轮速依赖。

> **构建状态**：提供完整 Android Studio Java 工程、GitHub Actions 构建工作流，已通过 Java 源文件语法解析与 XML 解析；受运行环境限制，**尚未完成 Gradle 编译或真机安装验证**。请将构建或运行报错反馈后修复。

## 构建与安装

* 推荐 Android Studio + JDK 17，打开 `parking-track-lab` 文件夹，同步 Gradle。项目使用 AGP 8.9.2、Gradle 8.12（CI）、Android SDK 35。
* 菜单 **Build → Build APK(s)**，待成功后 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，把 APK 传到 vivo X200 Pro，允许安装该来源的应用后安装。
* 如果用 GitHub Actions：推送代码到仓库 `main`、`master` 或 `experiment/*` 分支后，在 Actions 中运行 **Build debug APK**；下载 `ParkingTrackLab-debug-apk` 制品，解压后安装。`workflow_dispatch` 需工作流在默认分支存在。
* 也可让 Codex 在已有 Android 开发环境中运行：`gradle :app:assembleDebug`（首次构建需要下载 Android SDK/Gradle 依赖）。

## App 能做的事情

1. **步行实验**：固定步长（默认 0.70m，可调整）× 硬件计步 + 手机顶部方向（姿态旋转向量）；无硬件计步或权限时使用粗略加速度峰值兜底。
2. **驾车实验**：将 `TYPE_LINEAR_ACCELERATION` 变换到水平世界坐标后，保留两条路线：
   - 蓝线：加了死区和速度泄漏的**实验性积分**，绝不是可信导航；
   - 橙虚线：未经漂移修正的**原始二次积分**，用来直观看误差扩散。
3. **GPS 锚点**：GPS 提供的报告精度 ≤12m、时间较新且未发生不合理跳变时，自动用来设定原点或校正位置；失去可靠 GPS 后使用传感器继续推算。手机仅粗略定位时不会启用锚点。
4. **实时轨迹**：本地二维米制网格，正右为东，正上为北。起点原点、GPS 线、估计路线、标记点均显示在屏幕上。**这不是地下车库的真实平面地图**。
5. **记录数据**：记录加速度、陀螺仪、姿态旋转向量、压力、GPS、估计轨迹、计步和手动标记到 CSV。支持结束后通过系统分享面板导出最近一次文件。文件存放在应用专属外部 Documents/sessions 目录，不会上传云端。
6. **熄屏连续记录**：前台服务 + 常驻通知 + 最长两小时的部分唤醒锁。部分 vivo 系统后台节电策略仍可能中断采集，因此需要真机验证。

## 试验步骤（分开做，不要混在一次记录里）

**试验 A：室内闭环步行**

1. 开启手机定位服务，启动 App，授予**精确位置**、运动识别和通知权限。
2. 选**步行实验**，手机尽量拿稳，让手机**顶部朝前进方向**（手持方向会影响步行轨迹），点击**开始记录**。
3. 在同层室内沿约 10m × 10m 的方形路线走一圈回到同一地点，停下标记，点击结束。
4. 查看终点“距起点”是否接近 0m。这个数值是闭环误差，而非绝对定位精度。导出 CSV。不要在走路时低头看手机。

**试验 B：地下室步行**

* 重新启动一次步行实验，先走一个直线往返，再走一段带转角的路线；记录真实大概长度和转弯方向，结束后导出 CSV。
* 若室内始终没有可靠 GPS，就以 (0,0) 作为本地原点；**此时路线不能自动放到真实地图的经纬度上**。

**试验 C：驾车入库**

1. 在室外确保定位服务打开，选**驾车实验**。把手机**固定在车载支架**，全程不要挪动。
2. 车停稳、还没进入车库时点击开始，等 GPS 状态显示“用于校正”，然后正常行驶进入地下车库。
3. 停入车位后，安全停好车，再查看轨迹、点击**标记当前位置**、结束并导出 CSV。
4. 用真实停车点和入口相对位置、相对方向来核对终点位置。不要单看轨迹是否“形状像”就认定准确。
5. 如果方便，用同一路线至少重复 3 次，并记录停车点实际位置，以便计算每次终点偏差。

**重要：所有手机操作在安全停车状态下完成。不要在驾车时查看或操作屏幕。**

## 数据说明

CSV 包含：`elapsed_s`、`elapsed_realtime_ns`、`wall_time_ms`、`event`、`x,y,z,w`、`latitude,longitude`、`gps_accuracy_m`、`east_m,north_m`、`raw_east_m,raw_north_m`、`speed_mps`、`heading_deg`、`note`。

* `LINEAR_ACCEL` 是**手机设备坐标系**下去重力线性加速度；`ROTATION_VECTOR` 用于转到东-北-天坐标；`GYRO` 等是未处理原始读数。
* `GPS` 行的 `x,y` 是实际纬度和经度（历史字段名），`z` 是定位报告精度；同时 `latitude,longitude` 列也提供地理值。
* `ESTIMATE` 行对应轨迹估计；`STEP_ESTIMATE` 和 `MARK` 分别记录计步与手动标记。
* `east_m,north_m` 是蓝线估计；`raw_east_m,raw_north_m` 是橙虚线积分。位置不是可信真值，不可直接据此推定精度。
* 磁干扰、GPS 多路径、手机摆放角度、步长、系统算法都会带来误差。**仅凭最终坐标不足以量化误差，需要真实路线作为对照。**
* “连续 GPS 可用时”蓝线会用 GPS 校正；GPS 丢失后才主要靠 IMU，因此要分析地下阶段的漂移，不能将前段 GPS 校正视作纯惯性算法成功。

## 当前明确不支持

* 不提供真实车库室内底图、不贴合车道、不做可靠地图导航。
* 不提供车辆轮速、蓝牙自动启动、CarLife 连接识别、自动找车、Wi-Fi 指纹。
* 不支持每次历史记录的应用内列表；**一次只方便分享最近一条 CSV**（旧 CSV 文件仍在 app 专属目录中，卸载可能删除）。
* 不能保证系统杀后台或重启后续录，也不能保证真机传感器的稳定采样频率。
